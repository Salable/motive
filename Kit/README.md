# The Companion Kit

> **Audience:** anyone assembling a companion app, or drawing art for one.
> **Prerequisites:** none. Try a pack with `MOTIVE_SPRITE=Kit/packs/pip/sprite swift run motive-demo`.
> **Source of truth:** each pack's `pack.json`; the art is generated by `scripts/make-kit-art.py`; the assembly steps are [../docs/guides/ASSEMBLE-AN-APP.md](../docs/guides/ASSEMBLE-AN-APP.md).

Motive ships one app — `motive-demo`, Winston. Everything else you would need to
build a *different* one lives here as separate materials, because a companion is
a combination rather than a product: a sprite sheet, an idea of an app, a purpose
for the companion, and something for it to integrate with.

| Material | Where | What it decides |
| --- | --- | --- |
| The character | `Kit/packs/<id>/sprite/` | what it looks like and which states it can show |
| The purpose | `Kit/packs/<id>/pack.json` | who the companion is, what it is for, what it says first |
| The vocabulary | `pack.json` → `profile`, defined in [../docs/reference/STATE-PROFILES.md](../docs/reference/STATE-PROFILES.md) | which states the host can actually drive |
| The composition | [../docs/EMBEDDING.md](../docs/EMBEDDING.md) recipes, and [../Sources/MotiveDemo/main.swift](../Sources/MotiveDemo/main.swift) | which products the app links and what its `main.swift` contains |
| The integration | [../docs/INTEGRATIONS.md](../docs/INTEGRATIONS.md) | what drives it: REST, MCP, agent skills, hooks |

Assembling those into a runnable app is
[../docs/guides/ASSEMBLE-AN-APP.md](../docs/guides/ASSEMBLE-AN-APP.md). Apps land
in [../Apps/](../Apps/), which is gitignored: an assembled app is an ordinary
standalone SwiftPM package depending on the published Motive release, exactly
like one built by someone who never cloned this repository.

## Packs

A pack is **self-contained**: one directory holding a sprite package and the
prose that says what the companion is for. Copy the whole thing; nothing in a
pack refers to anything outside it.

| Pack | For | Drives |
| --- | --- | --- |
| [packs/pip](packs/pip/) | your own app's job lifecycle | `idle`, `working`, `waiting`, `review`, `failed` |
| [packs/caret](packs/caret/) | a CLI agent session (Claude Code, Codex) | the above plus `thinking` and `sleeping` |

Both draw the same nine states on the same 8×9 grid of 128×128 cells, so they
are interchangeable: swapping a pack is a directory copy and a name change, not
a rewrite.

### `pack.json`

Nothing in `Sources/` reads it — it is material for whoever (or whatever) is
assembling the app, and `KitTests` keeps it from lying about the art beside it.

| Field | Means |
| --- | --- |
| `id`, `title`, `blurb` | naming, and the one-line description |
| `purpose` | what this companion is *for*, in a sentence you could paste into a README |
| `sprite` | the sprite package directory, relative to the pack |
| `profile` | a heading slug in [../docs/reference/STATE-PROFILES.md](../docs/reference/STATE-PROFILES.md) — pinned by tests |
| `drives` | the states this pack promises the app will actually set; every one exists in the sprite, directly or through an alias |
| `voice`, `greeting` | the starting voice preference, and the first line it says |
| `capabilities` | the settings worth registering for it (see them rendered in [../docs/guides/DEMO.md](../docs/guides/DEMO.md)) |
| `integrations` | what it is meant to be driven by |

## Components

Reusable material that is not owned by one pack, in `components/`:

- [components/sprites/grid-template](components/sprites/grid-template/) — the
  kit grid drawn as guides and labels: safe area, centre line, ground line, and
  each cell's state name and frame number. It loads and animates like any other
  package, which is how a manifest that names the wrong row becomes a
  one-second observation instead of a debugging session.

[components/README.md](components/README.md) says what else belongs there.

## Regenerating the art

```sh
python3 scripts/make-kit-art.py     # needs Pillow
```

Deterministic, and the committed PNGs are its output — so edits made directly to
them are lost on the next run. Change the script, or copy the pack and repaint
your copy. [../docs/guides/SPRITE-DESIGN.md](../docs/guides/SPRITE-DESIGN.md) is
the drawing guide.
