# Kit Components

> **Audience:** anyone adding reusable material to the kit.
> **Prerequisites:** [../README.md](../README.md) for how packs and components differ.
> **Source of truth:** the directories beside this file; art here is generated by `scripts/make-kit-art.py`.

A **pack** is one companion, complete. A **component** is material that belongs
to no single pack — something more than one companion can be built out of. The
split matters because a pack is copied wholesale into an app and a component is
used while *making* one.

## What is here

| Component | What it is |
| --- | --- |
| [sprites/grid-template](sprites/grid-template/) | The kit grid as guides and labels: safe area, centre line, ground line, and each cell's state name and frame number. A loadable sprite package, so you can animate it to check a manifest. |

## What belongs here

- **Drawing aids** — grids, guides, palettes: anything that helps produce art on
  the kit's 8×9 / 128px lattice.
- **UI art** — badges, buttons, and other chrome an app might show beside the
  sprite. `SpriteBoxWindow` takes an `actions` array for buttons under the
  sprite ([../../docs/EMBEDDING.md](../../docs/EMBEDDING.md)); art for those
  goes here rather than inside one pack.

## What does not

- **Swift snippets.** The code that goes into an assembled app has one home
  already: [../../docs/EMBEDDING.md](../../docs/EMBEDDING.md) recipes, with
  [../../Sources/MotiveDemo/main.swift](../../Sources/MotiveDemo/main.swift) as
  the worked version. A second copy here would be a second thing to keep true.
- **Host wiring.** Hook commands, the Codex `notify` script, MCP registration —
  those live in [../../docs/reference/STATE-PROFILES.md](../../docs/reference/STATE-PROFILES.md)
  and [../../docs/INTEGRATIONS.md](../../docs/INTEGRATIONS.md), next to the
  explanation of when each event fires.
- **Anything one pack owns.** If only `caret` will ever use it, it goes in
  `packs/caret/`.
