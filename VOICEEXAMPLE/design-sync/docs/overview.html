TalkBox — design overview

Read this first: what TalkBox is, the principles, and the one deliberate asymmetry in an otherwise twin interface.

What this is

A macOS speech-queue appliance (Native SDK, Elm-architecture, GPU-rendered — no WebView) that now talks BACK. An agent POSTs text; a supervised sidecar speaks it aloud, one item at a time. An agent can also mark a note expects_response, and once the person has heard it they can type or speak an answer — transcribed on-device — which the agent reads back by polling the same job it already has an id for. No audio file is ever created, on either the speaking or the listening side.

Design principles

Agent-first entry: no quick-entry field anymore — everything arrives via REST, tray Reply, or history Requeue.
Current action is always visible: a Now-speaking card OR a Reply-needed card occupies the same slot, never both, never neither without reason.
Accent is reserved for ONE primary action per surface (Play, Send, Copy-AGENTS.md) plus the awaiting-reply LED; destructive is a fill only on Stop-recording.
Every command exists in ≥2 places: control, menu bar, shortcut, tray, or REST.
State survives quit — including an unresolved awaiting reply, restored exactly where it was, never silently dropped.
Escape hatches are mandatory wherever the queue can get stuck: Skip doubles as Decline, Clear reaches a stuck reply, the tray gets its own state.

The twin interface — and its one deliberate exception

Everything the window does, a separate process can do over the local REST API (port 4667, see GET /llms.txt / /openapi.json) — with ONE deliberate exception: there is no HTTP route to submit a reply. Answering is UI-only, on purpose, so a human-in-the-loop check can't be bypassed by the very agent asking the question. Everything else stays twin: POST /speak (now with expects_response) · /queue/play·pause·resume·skip·clear·remove·reorder · /settings (now with voice_replies_enabled) · GET /state·/jobs/{id} (now with response_state/response/response_via) · /agent-instructions.
