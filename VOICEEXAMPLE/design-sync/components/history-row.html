Rules

Newest first, last 8 kept. Only two chip tones exist: success for "done", disabled for everything else (skipped/failed print their own state word on the gray chip).
Chip is a fixed-width (64px) panel, not a flexible badge — <badge> ignores background/foreground overrides in this SDK, and a flexible width let long previews squeeze the chip down to "do…". Both problems drove this to a plain panel.
Duration is adaptive: "2.1 s" / "900 ms", not a raw millisecond count.
Requeue speaks the FULL original text under a fresh id (full text is retained on the archived item, not just the elided preview) — it does not carry over expects_response or the old response.
Requeue is a real <button size="sm" variant="ghost" foreground="accent"> — ghost is borderless and transparent at rest, so it still reads as the blue link. It replaced on-press on plain text: static text is drag-selectable in this SDK, so a slightly-moving click on the old link started a copy selection instead of the requeue.
Hairline separator between rows (<separator/>), not a full-width divider under the whole list.
