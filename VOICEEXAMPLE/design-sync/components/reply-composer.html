Voice sub-states

Idle — mic button shown ONLY if voiceRepliesEnabled (Settings → REPLIES). Off by default so no one who never wants this ever sees a mic permission prompt.
Recording — button becomes a filled destructive "Stop recording"; a 90s watchdog auto-stops if forgotten.
Transcribing — mic controls hide, a muted "Transcribing…" line shows; on-device Speech framework, streaming — no audio file is ever written, matching the TTS side's own invariant.
The transcript is populated for REVIEW, never auto-sent — a misheard word can be fixed before Send.

Escape hatches (mandatory, not polish)

Skip (⌘E) doubles as Decline while a reply is awaited — no separate shortcut to learn.
Clear reaches a stuck awaiting reply even with an empty pending queue — the confirm dialog resolves it as declined too.
The tray gets a 3rd icon state + a "Reply" row so the queue's stuck-ness is visible without the window open.
An awaiting reply survives an app restart (persisted, restored straight back into place) rather than being silently dropped.

There is no HTTP route to submit a reply — deliberately UI-only. An agent polls GET /jobs/{id} for response_state (none→awaiting→answered/declined); only a person, in the app, can resolve it. See AGENTS.md's "Asking for a reply" section for the full agent-side contract, including that a reply is real input (corrections, new instructions), not just yes/no.
